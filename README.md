# Гвинт

Мини-игра Гвинт из «Ведьмака 3» на Flutter (включая дополнения «Каменные сердца» и «Кровь и вино»). Это именно мини-игра из TW3, а не отдельная игра CD PROJEKT RED. Платформы: Android и iOS, портретная ориентация. В сторах приложение не публикуется: Android APK и iOS Ad Hoc.

## Что уже есть

- Партия по правилам Гвинта из TW3: пять фракций (Королевства Севера, Нильфгаард, Чудовища, Скоя'таэли, Скеллиге), лидеры, способности карт и перки фракций, три раунда, пересдача, жребий.
- Игра против бота и вдвоём на одном телефоне (hot-seat). У бота четыре уровня сложности: «Лёгкий», «Нормальный», «Тяжёлый» и «НА СМЕРТЬ!»; бот сам собирает колоду под уровень, фракция бота случайна ([ADR 0021](docs/adr/0021-bot-difficulty.md)). После партии можно сыграть реванш или выбрать другую колоду и фракцию, не выходя в меню ([ADR 0011](docs/adr/0011-match-flow.md)).
- Игра на двух телефонах по Wi-Fi: поиск партии в локальной сети, лобби, выбор колоды, отсчёт перед стартом, плашка связи («нестабильно», «нет связи», «хост свернул приложение») и окно обрыва, сдача и выход соперника, вход по QR-коду, если сеть не пропускает поиск, понятные экраны, когда Wi-Fi выключен или нет доступа к локальной сети, и вопрос хосту «Принять игрока …?» перед входом гостя.
- Игра на двух телефонах через интернет: на экране «Играть вдвоём» рядом с Wi-Fi способ «Через интернет». Хост создаёт комнату и видит крупный код из шести знаков (его можно скопировать или продиктовать), гость вводит код, хост принимает гостя; дальше та же партия, что по Wi-Fi. Понятные сообщения, когда сервис недоступен, код неверный, слишком много попыток или комната занята, закрыта или истекла ([ADR 0027](docs/adr/0027-online-screens.md)). Сервер: Supabase ([ADR 0025](docs/adr/0025-online-play-supabase-backend.md), [ADR 0026](docs/adr/0026-online-lobby.md)).
- Реванш в сетевой партии: кнопка «Реванш» после матча, 30 секунд на ответ соперника, затем снова выбор колоды в той же комнате ([ADR 0028](docs/adr/0028-network-tails-and-rematch.md)). В партии по сети соперник называется по имени из его настроек.
- Выбор фракции и колоды перед партией (лидер берётся из колоды), список колод и конструктор колод с проверкой правил сборки.
- Анимации розыгрыша карт, эффектов, конца раунда и матча.
- Звук: эффекты розыгрыша карт, способностей, погоды, хода, паса и конца раунда и матча, фоновая музыка по кругу; громкость музыки и эффектов из настроек работает, ползунок эффектов играет образец ([ADR 0023](docs/adr/0023-sound-and-music.md)).
- История партий и реплей: список сыгранных партий и просмотр партии с ботом или на одном телефоне на настоящем поле (пауза, шаги, перемотка по раундам, скорость, выбор места зрителя); реплей — это журнал (сид, колоды, ходы), который заново проигрывает движок, а у гостя сетевой партии — кадры его проекций ([ADR 0029](docs/adr/0029-history-and-replay.md)).
- Экран настроек (громкость, скорость анимаций).

Планы: Bluetooth LE как ещё один вид сетевой игры. Что делается прямо сейчас, видно по открытым pull request.

## Правила и данные

Источник правды по картам и правилам лежит в [docs/hand](docs/hand): правила в `main.md`, данные карт в `data/*.json`, колоды фракций в `cards/`. Изменения данных записываются в [docs/hand/CHANGELOG-data.md](docs/hand/CHANGELOG-data.md). UUID карты не меняется никогда: колоды и сетевой протокол ссылаются только на UUID.

Из этих данных `tools/build_pack` собирает пакет контента (формат и проверка: [ADR 0002](docs/adr/0002-content-pack.md)). Он попадает в `assets/content/`, это генерируемый каталог, в git он не хранится.

## Структура репозитория

| Путь | Что |
|---|---|
| `lib/`, `test/` | Flutter-приложение. Фичи лежат в `lib/src/features/<фича>/{domain,application,data,presentation}`, общее в `lib/src/core/`, точка сборки и навигация в `lib/src/app/` |
| `packages/gwent_engine` | движок правил: детерминированный, чистый Dart ([ADR 0001](docs/adr/0001-rules-engine.md)) |
| `packages/gwent_ai` | ИИ-соперник, жадный бот и его уровни сложности ([ADR 0004](docs/adr/0004-greedy-bot.md), [ADR 0021](docs/adr/0021-bot-difficulty.md)) |
| `packages/gwent_content` | пакет контента: модели, парсер, валидатор |
| `packages/gwent_net` | сетевой протокол: сообщения, хост и клиент партии, переподключение ([ADR 0005](docs/adr/0005-network-protocol.md)) |
| `tools/build_pack` | сборка и проверка пакета контента из `docs/hand` |
| `tools/app_icon` | исходники иконки приложения и скрипт растеризации |
| `tools/audio` | скрипты перевода звуков и музыки в AAC, откуда файлы и под какой лицензией ([ADR 0023](docs/adr/0023-sound-and-music.md)) |
| `tools/scripts/setup.sh` | подготовка: зависимости и кодогенерация |
| `supabase` | серверная часть игры через интернет: миграции Supabase и тесты политик ([ADR 0025](docs/adr/0025-online-play-supabase-backend.md), [supabase/README.md](supabase/README.md)) |
| `docs/hand` | данные карт и правила игры |
| `docs/adr`, `docs/spec` | архитектурные решения и требования к фичам |
| `drift_schemas/` | схемы базы пользовательских данных всех версий для миграций |

Архитектура — чистые слои: domain, application, data и presentation, зависимости направлены к домену. Это проверяет `test/architecture_test.dart`, а чистоту пакетов — `test/purity_test.dart` в каждом из них. Подробности: управление состоянием и внедрение зависимостей — [ADR 0003](docs/adr/0003-state-management-and-di.md); сессия матча — [ADR 0006](docs/adr/0006-match-session.md); Wi-Fi — [ADR 0007](docs/adr/0007-wifi-transport.md), [ADR 0019](docs/adr/0019-wifi-multiplayer.md) и [ADR 0020](docs/adr/0020-wifi-qr-and-link-quality.md); защита сетевой игры — [ADR 0022](docs/adr/0022-network-hardening.md); звук и музыка — [ADR 0023](docs/adr/0023-sound-and-music.md). Полный список решений: [docs/adr](docs/adr).

Основные технологии: Flutter, `flutter_bloc` (Cubit/Bloc), `go_router`, Drift для пользовательских данных (колоды, результаты матчей, настройки), `bonsoir` и WebSocket для игры по Wi-Fi, `qr_flutter` и `mobile_scanner` для QR-кода партии, `audioplayers` для звука и музыки, локализация через `gen-l10n` (пока только русский).

## Быстрый старт

Нужны Flutter 3.41.0 и Dart 3.11.0: ровно эти версии стоят на Mac разработчика и в CI. Другая версия Flutter меняет в `pubspec.lock` пакеты, закреплённые SDK; такие правки коммитить не нужно, а `setup.sh` предупреждает о несовпадении версии.

```sh
tools/scripts/setup.sh   # зависимости, пакет контента, кодогенерация, иконки
flutter run              # запуск на подключённом устройстве или симуляторе
```

`setup.sh` нужно запускать после каждого `git pull` и перед проверками: сгенерированный код (`*.g.dart`, `*.freezed.dart`, вывод `gen-l10n`, шаги миграций) в git не хранится. Скрипт также принимает папку пакета: `tools/scripts/setup.sh packages/gwent_engine`. Все команды подготовки и кодогенерации живут только в нём.

## Проверка

Те же команды запускает CI, из корня после полного `setup.sh`:

```sh
dart format --output=none --set-exit-if-changed .
flutter analyze --fatal-infos   # приложение, packages/ и tools/
flutter test                    # тесты приложения
```

Тесты пакетов запускаются из их папок: `dart test`. Для пакетов и утилит из `tools/` после `setup.sh` достаточно Dart SDK, Flutter не нужен; полный набор команд и правила линтера — в [CLAUDE.md](CLAUDE.md).

## Сборка и установка

- Android: `flutter build apk --release`.
- iOS: сборка Ad Hoc под корпоративным аккаунтом Apple Developer, выполняется на Mac.
- Игре по Wi-Fi нужен доступ к локальной сети: на iOS система запросит доступ к локальной сети, на обоих телефонах нужна одна Wi-Fi сеть. Для входа по QR-коду приложению нужна камера.

## Разработка

Прямые пуши в `main` и `dev` запрещены: изменения идут через pull request в `dev`, выпуск в `main` — PR `dev → main`. Каждый PR проходит CI и ревью.

Правила для разработчиков и агентов, линтер, команды и соглашения по коду описаны в [CLAUDE.md](CLAUDE.md).
