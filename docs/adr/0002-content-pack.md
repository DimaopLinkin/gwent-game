# 0002. Пакет контента: формат, сборка, проверка

Статус: принято в PR «Пакет контента», ждёт аппрува. Основа: проект `content_import_design.md` (11.10.2026).

## Контекст

Данные карт живут в `docs/hand/data` (12 таблиц JSON с UUID-ключами), правила в `docs/hand/main.md`. Приложению,
сетевой игре и серверу (позже) нужен один неизменяемый артефакт с версией и хешем, который проверяется одинаково,
откуда бы он ни пришёл. Логика способностей живёт в движке, в данных только параметры.

## Решение

### Файлы

```
assets/content/gwent-w3-base/   # собирает tools/scripts/setup.sh, не коммитится
  manifest.json
  pack.json          # правила: всё, что входит в content_hash
  strings.ru.json    # тексты: ключ строки → текст
```

Все три файла пишутся каноническим JSON: ключи объектов отсортированы по кодовым единицам UTF-16, пробелов нет,
строки экранируются как в `jsonEncode`, дробных чисел нет. Одинаковые данные дают побайтово одинаковый пакет,
поэтому ассет и пакет на сервере одной версии совпадают.

### manifest.json

| Поле | Значение |
|---|---|
| `format_version` | `1`. Любое изменение формата повышает версию: парсер отклоняет неизвестные поля |
| `pack_id`, `pack_version`, `min_engine_version` | из `docs/hand/content_pack.json`; `pack_version` повышается при каждой правке данных |
| `content_hash` | `sha256:<hex>` канонического JSON правил. Совпадает с SHA-256 файла `pack.json` |
| `locales` | языки строк; запасной `ru` есть всегда |
| `files` | `[{path, sha256, size}]`: ровно `pack.json` и `strings.<locale>.json` каждого языка |

`created_at` и `signature` из проекта пока не вводятся: дата делает сборку невоспроизводимой, а подпись нужна
только пакетам с сервера. Подпись появится вместе с `RemoteContentSource` и новой версией формата.

### pack.json

Таблицы: `game_rules` (объект), `zones`, `fractions`, `fraction_abilities`, `squad_abilities`, `special_abilities`,
`leader_abilities`, `squad_cards`, `special_cards`, `leader_cards`. Записи отсортированы по UUID.

- Тексты заменены ключами `name_key`, `description_key` вида `<сущность>.<uuid>.<поле>`.
- У зон закрытый ключ `melee`, `ranged`, `siege`, `agile`; у фракций ключ латиницей (`skellige`). Транслитерированные
  `tag` в пакет не попадают.
- `game_rules`: `crystals`, `starting_hand_size`, `max_redraws`, `min_squad_cards`, `max_special_cards`. Источник
  значений: `docs/hand/data/game_rules/game_rules_data.json`, а в него они перенесены из `main.md` (разделы 1–3, 2.1).
- У способности `effect` из закрытого списка `EffectKey` (`packages/gwent_content/lib/src/model/effect_key.dart`)
  и общие `params`; у карты свои `ability_params`. Параметры эффекта это `params` способности вместе
  с `ability_params` карты, ключи не пересекаются, состав и типы проверяются по описанию эффекта.

| Связь в `docs/hand` | В пакете |
|---|---|
| `twin_config` | `muster` с `summons: [uuid…]` у карты-триггера |
| `bait_config` | `bait` с `summons: uuid` |
| `mardrem_config` | `berserk` с `transform_to: uuid` |
| ряд Казни отряда | `scorch_row` с `row` из зоны карты и общим `threshold: 10` |
| лидер «сыграть погоду из колоды» | `play_weather_from_deck` с `card_id` спецкарты погоды |

Отличие от проекта: Двойник хранит явный список `summons`, а не общий ключ группы. Связи в данных
несимметричны (Огромный главоглаз призывает Главоглазов, обратного нет; Керис призывает Воительниц клана Друммонд),
а группа этого не выражает. Прочная связь параметров не имеет: копии одной карты имеют один UUID, а валидатор
проверяет, что название такой карты уникально.

### Проверка

Пять уровней, загрузчик останавливается на первом с проблемами и возвращает их все:

1. **Целостность**: файлы читаются, размер и SHA-256 совпадают с манифестом, `content_hash` равен хешу
   канонического JSON правил (переформатированный `pack.json` с верным манифестом допустим).
2. **Совместимость**: `format_version`, `min_engine_version` не выше версии движка, каждый эффект есть
   в `EngineCapabilities.knownEffects`. Эффект, которого не знает формат, тоже проблема совместимости.
3. **Схема**: обязательные поля, типы, диапазоны, формат UUID, нет лишних полей.
4. **Ссылки**: UUID уникальны во всём пакете, ключи зон и фракций уникальны, ссылки и параметры-ссылки ведут
   в нужные таблицы, параметры эффектов полные; у каждого ключа есть текст на каждом языке, лишних текстов нет.
5. **Инварианты** (`main.md`): все четыре зоны; у фракции с колодой есть лидер и хватает копий карт отрядов вместе
   с нейтральными (`min_squad_cards`); лидеры только у фракций с колодой; герой в одном экземпляре; созданные карты
   (`count` = 0) достижимы через Приманку или Берсерка, а их цели в колоду не кладутся и не создают новых;
   Двойник призывает карты из колоды, призыв своих копий требует больше одной копии; Проворство задаётся зоной;
   название карты с Прочной связью уникально.

Уровни 3–5 доступны отдельно (`validateContent`) для CI и агента-валидатора данных.

### Код

| Где | Что |
|---|---|
| `packages/gwent_content` (domain, чистый Dart) | модели, `EffectKey`, кодеки, канонический JSON и хеш, валидатор, `ContentSource`, `InMemoryContentSource`, `ContentPackLoader`, `buildContentPack` |
| `tools/build_pack` | конвертер `docs/hand/data` → правила и строки, CLI сборки; результат проверяется тем же загрузчиком |
| `lib/src/features/content/data` | `AssetContentSource` поверх `AssetBundle` |

`gwent_content` не зависит от `gwent_engine`: версию движка и список эффектов приложение передаёт загрузчику
как `EngineCapabilities` из точки сборки. Сопоставление `EffectKey` с типами движка делается отдельной задачей.

## Отвергнутые варианты

- **Коммитить собранный пакет.** Расходился бы с `docs/hand` после каждой правки данных; по правилу CLAUDE.md
  генерируемое не коммитится, а сборка детерминирована.
- **Группа вместо списка для Двойника.** Теряет несимметричные связи.
- **Хеш по байтам файла.** Переформатирование меняло бы хеш без изменения смысла.
- **Читать `docs/hand/data` в приложении напрямую.** Нет версии, хеша и единой проверки для сетевой игры.
