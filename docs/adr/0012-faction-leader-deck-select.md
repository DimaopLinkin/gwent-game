# 0012. Выбор фракции, лидера и колоды перед партией

## Контекст

Макет 7 (`gwent/design/07-faction-select.html`) заменяет временный экран выбора колод из ADR 0011: игрок выбирает фракцию, потом лидера, потом колоду. Макет 8 (конструктор колоды) делается отдельным запросом и дополнит этот ADR. Сетевые состояния макетов 7–8 (вход из лобби, обрыв связи, «Оба игрока готовы») сюда не входят: экраны только готовы к подключению к лобби позже (ADR 0007).

## Решение

### Порядок шагов

Каждое место проходит три шага: **фракция** (карусель с гербом и способностью фракции), **лидер** (сетка карт лидеров фракции и способность выбранного), **колода** (список колод этой фракции). В hot-seat сначала выбирает первое место, потом второе; против бота выбирает только первое.

Держатель — `MatchSetupCubit` (`features/match/presentation/`), состояния `MatchSetupLoading`, `MatchSetupReady`, `MatchSetupDone(request)`, `MatchSetupFailed`. В `Ready` лежат место, шаг (`SetupStep`), правила, номер фракции, лидер и колоды с проблемами (`DeckChoice`). Экраны (`presentation/setup/`) — `FactionSelectView`, `LeaderSelectView`, `DeckSelectView`; `MatchSetupStage` соединяет их с держателем. Шаг и «назад» ведёт держатель: с первого шага первого места «назад» выходит из выбора, иначе возвращает на шаг назад, со второго места — к колоде первого.

### Лидер партии заменяет лидера колоды

Лидер, выбранный на втором шаге, действует только в этой партии: `LocalMatchRequest` несёт `leaderOne`/`leaderTwo`, `StartMatch` ставит их в колоду (`Deck.copyWith(leaderId:)`) перед проверкой. Сохранённая колода не меняется. Колода годна, если проходит `DeckRules.check` с выбранным лидером: лидер чужой фракции даёт `DeckRuleViolation(LeaderNotDeckFaction)` из движка.

### Колоды и бот

- В списке только колоды выбранной фракции (`DeckRules.deckFactions`). Если у фракции нет годной колоды, стартовую создаёт `GetActiveDeck` (ADR 0008), поэтому список не пустой; созданную колоду держатель добавляет к снимку сам, не дожидаясь потока.
- Предвыбрана активная колода фракции, если она годится с выбранным лидером, иначе первая годная, иначе первая. Негодная колода видна с причиной (`DeckIssueText`), выбрать её можно, играть нельзя. Из списка можно перейти в конструктор («Изменить»); список обновляется по потоку колод и не возвращает игрока на шаг назад.
- Подтверждённая колода становится активной колодой своей фракции (`SetActiveDeck`). Если она годится только с выбранным лидером, активной остаётся прежняя колода фракции.
- Колоду бота даёт `ChooseOpponentDeck`: активная колода следующей по порядку пакета фракции после фракции игрока (после последней идёт первая). Фракции в партиях против бота чередуются сами, без выбора. `ChooseDefaultDecks` (две первые фракции) удалён.

### Данные для экранов

`DeckRules.factionInfos` отдаёт `FactionInfo` и `LeaderInfo` с готовыми текстами из строк пакета: экран не знает ключей. Имена лидеров делит `splitLeaderName` по двоеточию на персонажа и прозвище. Коллекции игрока пока нет (все карты пакета доступны сразу), поэтому `LeaderInfo.available` всегда `true`; экран уже умеет показывать недоступного лидера с замком, кнопка для него погашена. `GwentFaction.accent` — цвет фракции для колец и полос.

На низком экране (< 720 pt) шаг лидера прокручивается целиком, а кнопка остаётся внизу.

### Отложено

Конструктор колоды (макет 8) и список колод; значок «герой ×1» в списке не нужен: герои в пакете имеют `count` 1. Сетевые состояния макетов 7–8. Настоящая коллекция лидеров.

## Отвергнутые варианты

- **Лидер сохраняется в колоде.** Выбор лидера на шаге 2 меняет колоду навсегда, а колода принадлежит конструктору; перекрывать его выбор перед матчем — неожиданно.
- **Игрок выбирает фракцию бота.** Макет такого шага не имеет, а чередование даёт разнообразие без лишнего экрана.
- **Один экран вместо трёх шагов.** Не помещается на малых экранах и расходится с макетом.

## Статус

Принято.
