# 0001. Движок правил `gwent_engine`

## Контекст

Правила мини-игры описаны в `docs/hand/main.md`. Движок должен работать без устройства (тесты, хост сетевой партии,
позже сервер), быть детерминированным и прятать скрытую информацию (сетевая спецификация, раздел 2.1 и 4).
Параметры карт приходят из пакета контента, логика способностей живёт в коде движка.

## Решение

### Контракт

- `MatchEngine` (реализация `GwentEngine(catalog, rules: GameRules())`):
  - `start(MatchSetup)` → `EngineResult`: проверка колод, подготовка партии до первого решения игрока;
  - `apply(state, seat, intent)` → `Accepted(state, events)` или `Rejected(Reject)`; входное состояние не меняется;
  - `project(state, seat)` → `PlayerView`;
  - `eventsFor(events, seat)` → события, которые можно отправить игроку;
  - `validateDeck(deck)` → нарушения правил сборки колоды.
- Намерения (`Intent`): `RedrawCard`, `FinishRedraw`, `PlayCard(card, row?, target?)`, `UseLeader`, `Pass`,
  `ChooseOption(option)`, `Resign`. Отказ типизирован: `RejectReason`.
- `GameRules` хранит числа из правил (размер руки, замены, кристаллы, 22 отряда, 10 специальных карт); позже их задаст
  таблица `game_rules` пакета контента.

### Доменные типы карт

Типы принадлежат движку; пакет контента строит из своих таблиц `CardCatalog`.

- `UnitCardDefinition` (размещение `melee/ranged/siege/agile`, сила, герой, способность), `SpecialCardDefinition`,
  `LeaderDefinition`; фракция — `Faction` с перком `FactionPerk`.
- Способности — закрытые `sealed`-иерархии с параметрами: `MusterAbility(summons)` вместо `twin_config`,
  `BaitAbility(summon)` вместо `bait_config`, `BerserkAbility(transformsInto)` вместо `mardrem_config`,
  `WeatherAbility(rows)`, `ScorchRowAbility(row, threshold)`, `PlayWeatherFromDeckAbility(card)`, `LeaderHornAbility(row)` и т. д.
- У каждой способности есть машинный ключ (`key`); их объединение — `knownEffects`. Пакет контента с ключом не из
  этого списка несовместим с движком. Ключи совпадают со словарём поля `effect` пакета контента (вводится PR пакета
  контента). Пять ключей общие для разных видов карт: `commander_horn`, `scorch`, `mardroeme`, `clear_weather`,
  `scorch_row`; рог лидера по словарю контента отдельный, `leader_horn`.
- Созданная карта — карта отряда с `copies = 0`.

### Состояние и разрешение действий

- `MatchState` неизменяем и сравнивается по значению. `apply` работает с изменяемой копией (черновиком) и отдаёт новое
  состояние.
- Действие раскладывается на шаги в стеке эффектов состояния. Шаг, которому нужно решение игрока, останавливает
  разрешение и выставляет `PendingChoice` (кто выбирает, вид выбора, варианты). Ответ — `ChooseOption`, после него
  стек продолжается. Так цепочки «Медик → Медик → Шпион», выбор ряда проворной карты, выбор лидера и решение Скоя'таэлей
  работают одинаково, а между выборами состояние можно сохранить и передать по сети.
- Пока партия ждёт выбора, ход не переходит; другие намерения отклоняются (`choicePending`). Сдача разрешена
  и снимает выбор.
- Вариант выбора карты (`CardOption`) несёт экземпляр целиком, с `cardId`: выбор из колоды отрисовывается по одной
  проекции, без доступа к скрытым зонам.

### Случайность

- Генератор `Rng` неизменяем и хранится в состоянии; по умолчанию `SeededRng` (SplitMix64, алгоритм в коде, а не
  `dart:math`, чтобы последовательность не зависела от SDK). Арифметика рассчитана на нативные платформы.
- Порядок вызовов — раздел 12 правил. Номера экземпляров карт — случайная перестановка номеров обеих колод
  (сетевая спецификация, раздел 4): по номеру нельзя узнать ни карту соперника, ни её место в колоде. Номера по порядку
  перемешанной колоды выдавали бы пересдачу: карта с номером сразу после стартовой руки пришла при замене.
  Созданные карты (открытые) получают следующие номера по порядку.

### Скрытая информация

- `PlayerView`: своя рука, чужая рука и обе колоды только количеством; варианты выбора соперника не видны.
- `eventsFor`: взятые соперником карты превращаются в `CardsDrawnHidden(count)`, замены при пересдаче и показ руки
  Императором Нильфгаарда уходят только своему игроку, варианты выбора соперника убираются. Видимость задана для
  каждого события явно: новое событие не скомпилируется, пока для него не решено, что видит соперник.
- `UnitPlaced` от Двойника называет зону (`musterFromDeck`/`musterFromHand`), чтобы соперник по событиям вёл число
  карт руки и колоды.
- Показ руки Императором живёт только в событии; в проекции его нет, после восстановления по снимку он не
  повторяется.

### Толкования правил, которых нет в спецификации явно

- Прочная связь считает карты того же определения (в данных у копий один UUID и одно название).
- Двойник берёт карты по порядку `summons`: сначала из колоды, затем из руки. Связь задаётся списком призываемых
  карт, а не общей группой из `content_import_design.md`: в правилах она несимметрична (Огромный главоглаз
  призывает Главоглазов, но не наоборот).
- Проворной карте, которая выходит на поле не из руки (Медик, Двойник, перк Скеллиге), ряд выбирает игрок.
- Приманка, уничтоженная Казнью, призывает карту на своё место, если ряд совпадает, иначе в конец ряда призванной карты.
- Убийца Оберона: карты сбрасываются по одной, затем выбирается карта колоды. Варианты из колоды упорядочены
  по номеру экземпляра, а не по порядку колоды.
- Надежда Aen Seidhe перебирает все раскладки; передвинутые карты встают в конец ряда.
- При уборке поля карты уходят в отбой в порядке: игрок, который начнёт следующий раунд, затем соперник; ряды ближний,
  дальний, осадный, в каждом ряду карты по выкладке, затем слот рога; в конце зона погоды.

## Отвергнутые варианты

- `freezed` для состояния: кодогенерация ради равенства не окупается, а строгий набор правил линтера плохо уживается
  с генерированным кодом.
- Все решения в самом намерении (`PlayCard` с целью Медика и рядами всех карт цепочки): цепочки заранее неизвестны,
  а случайный Медик при «Завоевателе Севера» вообще не даёт выбора.
- `dart:math` `Random(seed)`: последовательность не закреплена контрактом SDK.
